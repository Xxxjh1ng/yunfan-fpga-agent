# 上板指南：在芯路恒 ACG720（高云 GW5AT-138）上跑通「闪灯」与更多演示

> 本文记录 **2026-10-29 真机实测全过程**：从零装工具链、解决驱动与 license、确认引脚，
> 到把云帆生成的比特流真正烧进板子并看到 LED 动作。
> 板卡：**芯路恒 / 小梅哥 ACG720-V3-BJ**（FPGA：GW5AT-138，板载下载器）。

---

## 0. 这块板子是什么（实测结论）

| 项目 | 实测值 | 来源 |
| --- | --- | --- |
| FPGA | `GW5AT-LV138PG484AC1/I0`（GW5AT-138**B**，PBGA484） | 厂商例程 `ch2_led_flash/src/led_flash.cst`、`led_flash.gprj` |
| JTAG IDCODE | `0x0011081B` | `programmer_cli --scan` |
| 电源输入 | **9–12V DC**（`J4 jack_power`），板上另有**电源开关** | 板卡丝印 + 原理图 `12_BoardPower` |
| 下载器 | 板载 **Gowin USB Cable (FT2CH)**，USB-C 直连，无需外部下载器 | `--scan-cables` |
| 时钟 | 50 MHz → `Y18` | 厂商例程 CST |
| 复位 | `rst_n` → `B21`（另有按键 S0=F15、S1=A20、S2=B20、S3=A21） | 同上 + 管脚分配表 |
| 用户 LED | `led[0..8]` = `M22, N22, L21, K21, K22, J22, H22, M21, N19` | 管脚分配表 |
| 拨码开关 | `sw[0..7]` = `G22, D22, E22, G21, E21, D21, C22, B22` | 管脚分配表 |
| 串口 | `uart_tx=M15`、`uart_rx=J21`（FT2CH 的 UART 通道 → `COM6`） | 管脚分配表 |

> ⚠️ **教育版云源不支持 GW5AT-138**（器件库只有 GW1N/GW2A/GW5A-25A 共 9 款）。
> 必须用**完整版**（本项目实测 V1.9.12）+ license。

## 1. 一次性准备

### 1.1 工具链

```powershell
# 完整版云源（本项目用的是厂商资料包里的 V1.9.12）
# 安装后确认器件表里有 GW5AT-138
Get-Content "C:\Gowin\Gowin_V1.9.12_x64\IDE\share\device\device_info.csv" | Select-String "GW5AT-138"
```

`yunfan` 会自动发现工具链，且**优先选版本更高、非 Education** 的安装：

```powershell
python -m yunfan doctor
# gw_sh -> C:\Gowin\Gowin_V1.9.12_x64\IDE\bin\gw_sh.exe
```

### 1.2 License

两条路，任选：

**A. 官网正式 license（推荐）**——高云官网申请，绑定网卡 MAC，1–2 个工作日回传，放到
`C:\Gowin\gowin.lic`（`IDE\bin\gwlicense.ini` 默认就指向它）。

**B. 厂商应急 license（当天可用）**——厂商资料包里的 `gowin_E_D4D853392AD8.lic`，
要求把**以太网网卡 MAC 改成 `D4D853392AD8`**：

```powershell
# 改 MAC（会重拨 DHCP，几秒恢复）
Set-NetAdapter -Name "以太网" -MacAddress "D4-D8-53-39-2A-D8" -Confirm:$false
Copy-Item "<资料包>\gowin_E_D4D853392AD8.lic" "C:\Gowin\gowin.lic" -Force

# 用完想恢复网络身份（把后面的地址换成你本机原来的 MAC）
Set-NetAdapter -Name "以太网" -MacAddress "AA-BB-CC-DD-EE-FF" -Confirm:$false
```

### 1.3 USB 下载器驱动（**最容易翻车的一步**）

插上板子后，设备管理器里若出现 `USB Serial Converter` 带**黄色感叹号**（Problem code = 10），
说明 Gowin 的 FTDI 驱动没起来。此时 `programmer_cli --scan` 会报
`Error: No Gowin devices found!`——**看起来像没上电，其实是驱动问题**。

修复顺序：

```powershell
# 1) 先装驱动（云源自带）
& "C:\Gowin\Gowin_V1.9.12_x64\Programmer\driver\GowinUSBCableDriverV5_for_win7+.exe" /S

# 2) 关键一步：禁用再启用该设备（等效热插拔，触发驱动重新绑定）
$inst = (Get-PnpDevice | Where-Object { $_.InstanceId -like "*VID_0403*" }).InstanceId
Disable-PnpDevice -InstanceId $inst -Confirm:$false
Enable-PnpDevice  -InstanceId $inst -Confirm:$false

# 3) 再扫，应能看到 IDCODE
& "C:\Gowin\Gowin_V1.9.12_x64\Programmer\bin\programmer_cli.exe" --scan -d GW5AT-138B
```

正常输出：

```
Target Cable: Gowin USB Cable(FT2CH)/0/None/null@2.5MHz
Device Info:
    Family: GW5AT
    ID: 0x0011081B
 1 device(s) found!
```

> 扫描提示 `Name: ... (One of them)` 是正常的：同一个 IDCODE 对应多个封装/版本型号，
> 烧录时用 `--device GW5AT-138B` 明确指定即可。

## 2. 上板运行

### 2.1 顺序（重要）

1. **先上电**：9–12V 适配器插 `J4`，打开板上**电源开关**，确认电源灯亮
2. **再插 USB**：插到下载器那一路 USB-C（板上一般标 `USB`/`JTAG`）
3. 跑 `detect` 确认链路上有器件

> 先插 USB 后上电会出现"下载器在、FPGA 不在"的假象，白白怀疑接线。

### 2.2 四个演示

```powershell
cd <项目根>

# ① 1 Hz 闪灯（最简链路验证）
python scripts/hw_demo.py detect --device GW5AT-138
python scripts/hw_demo.py run --device GW5AT-138 --board acg720 `
       --clk-pin Y18 --led-pin M22 --program sram

# ② 8 灯流水灯（每 0.25 s 移动一位）
python scripts/hw_run.py run led_water

# ③ 8 位拨码 PWM 调光（SW0..SW7 改占空比，LED0 亮度随之变化）
python scripts/hw_run.py run pwm_sw

# ④ SW0 使能的二进制计数器（LED0..3，0→15 循环）
python scripts/hw_run.py run key_count

# 只看效果不烧录
python scripts/hw_run.py build led_water
```

`--program sram` / `--run 2` = **下载到 SRAM，断电即消失**，不覆盖板载 Flash 里的出厂程序。
想掉电保留才用 `--flash`（`--run 9`，会覆盖出厂例程）。

### 2.3 实测结果（GW5AT-138B，50 MHz 约束）

| 设计 | 资源 / 时序 | 比特流 | 烧录耗时 |
| --- | --- | --- | --- |
| `blink`（1 Hz 闪灯） | Logic 45/138240，Register 33，Fmax **117.7 MHz** | 33.08 MB | 7.5 s |
| `led_water`（流水灯） | Fmax **187.6 MHz** | 33.08 MB | ~8 s |
| `pwm_sw`（拨码调光） | Fmax **589.5 MHz** | 33.08 MB | ~8 s |

> 138K 器件的比特流本身就 33 MB，比 GW5A-25A 的 5.68 MB 大 6 倍，属正常。

## 3. 踩过的坑（症状 → 根因 → 处置）

| 症状 | 根因 | 处置 |
| --- | --- | --- |
| `can't find device: GW5AT-LV138PG484AC1/I0` | 教育版没有该器件 | 换完整版 V1.9.12 |
| `License verification failed  File can not be opened.` | 没放 license 文件 | 放到 `C:\Gowin\gowin.lic` |
| `License hostid not match.` | license 绑定 MAC ≠ 本机 MAC | 改网卡 MAC（应急）或申请正式 license |
| 电源灯不亮 | 适配器是 5V；板子要 **9–12V**；电源开关没开 | 换适配器 + 开关拨 ON |
| `No Gowin devices found!`（下载器却能识别） | ① FTDI 驱动 Problem=10 ② 先插 USB 后上电 | 禁用/启用设备后重扫；先上电再插 USB |
| `there are more than one device named GW5AT-LV138PG484AC1/I0` | 138B/138C 共用 part number | Tcl 里 `set_device <pn> -device_version B` |
| 烧录进程卡死 400 s、CPU 仅 0.3 s | **用管道截断**烧录输出，子进程写满缓冲区被阻塞 | 用文件重定向接收输出，勿用 `Select-Object -First N` 截断 |
| 烧到一半被杀 → 之后扫描一直挂 | FPGA TAP 卡在中间状态 | 断电重启板卡 + 重新插拔 USB |

## 4. 结束测试

1. **关板卡电源开关** → SRAM 配置消失；下次上电自动从板载 Flash 启动出厂程序
   （全程未写 Flash，板子与拿到时一致）
2. 再拔 USB
3. 关闭云源相关进程（正常烧录结束后无残留）
4. 若不再用应急 license，把 MAC 改回原值（见 §1.2）

## 5. 引脚是如何确定的（可复现）

```powershell
# 1) 从厂商例程 CST 拿到黄金参考：clk=Y18 / rst_n=B21 / led=M22
#    <资料包>\02_例程源码\GW5AT138K\第2章...\ch2_led_flash.rar

# 2) 从管脚分配表批量导入其余引脚（自动生成 boards.json 与 .cst 预览）
python scripts/import_pinout.py "C:\fpga\04_引脚功能信息\高云 ACG720-138&60K通用管脚分配表.xlsx" `
       --board acg720 --write

# 3) 核对结果
python -c "from yunfan.config import BoardProfile; b=BoardProfile.load('acg720'); print(b.pins)"
```

> 经验：**先找厂商例程里的 `.cst`，再信管脚分配表**。两者一致才用；
> 只有表格没有例程时，务必先做 `led_water` 这类"看得见"的验证。
